КАРТА ЛПУ 2.0 — спільна база спеціальностей з реєстрацією за прізвищем

ФАЙЛИ
- index.html, app.js, styles.css, data.json — сайт
- supabase_setup.sql — таблиці та RLS-політики
- supabase/functions/admin-login/index.ts — серверна перевірка адміністратора

ВАЖЛИВО ПРО БЕЗПЕКУ
Пароль адміністратора НЕ зберігається в браузері та НЕ вбудований у app.js. Він перевіряється серверною Edge Function. У Supabase треба задати ADMIN_PASSWORD=2237 та ADMIN_SURNAME=<прізвище адміністратора> як secrets функції.
Звичайні користувачі входять без пароля через Supabase Anonymous Auth, вказуючи прізвище. Це дає технічний ID сесії, але не підтверджує справжню особу: користувач може вказати чуже прізвище. Для гарантованої ідентифікації потрібна авторизація з підтвердженням пошти/телефону.

НАЛАШТУВАННЯ SUPABASE
1. У Dashboard > SQL Editor виконайте повністю supabase_setup.sql.
2. У Dashboard > Authentication > Sign In / Providers увімкніть Anonymous Sign-Ins.
3. Встановіть Supabase CLI та увійдіть у нього: supabase login.
4. У терміналі з кореня папки білда зв'яжіть проєкт:
   supabase link --project-ref zaoiiafrryeajwoltzvo
5. Задайте secrets (замініть ПРІЗВИЩЕ_АДМІНА на точне прізвище адміністратора):
   supabase secrets set ADMIN_PASSWORD=2237 ADMIN_SURNAME="ПРІЗВИЩЕ_АДМІНА"
6. Розгорніть функцію:
   supabase functions deploy admin-login

ПУБЛІКАЦІЯ
Завантажте index.html, app.js, styles.css, data.json на GitHub Pages. Папку supabase також збережіть у репозиторії для подальшого керування Edge Function.

РОБОТА
- Користувач вводить прізвище, залишає поле пароля порожнім і натискає «Увійти».
- Адміністратор вводить своє прізвище та пароль 2237.
- Автор додавання зберігається у added_by_surname разом із user_id.
- Видаляти додані спеціальності може лише профіль адміністратора; це додатково перевіряється RLS у базі.
- Усі відвідувачі можуть переглядати додані спеціальності після входу.

Після виконання SQL та розгортання Edge Function функціональність буде активною. Сам архів не може самостійно змінити налаштування твого Supabase.
